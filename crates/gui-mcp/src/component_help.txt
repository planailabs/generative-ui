Generative UI components — write the surface as an HTML string for publish_surface's `html`
field, composing these `<ui-*>` elements:

<ui-heading level="1-3">Title</ui-heading>
<ui-text>Body copy.</ui-text>
<ui-card> ...elements... </ui-card>
<ui-button data-action="act" data-value='{"any":"json"}'>Label</ui-button>
    Clicking sends a backflow event with this action and value.
<ui-input name="field" label="..." placeholder="..." type="text|email|number|...">
<ui-select name="field" label="..."><option value="v">V</option>...</ui-select>
<ui-checkbox name="field" checked>Label</ui-checkbox>
<ui-form data-action="submit_act"> ...inputs... </ui-form>
    Submitting sends one backflow event whose value is { field: value, ... } for all named
    inputs. A submit button is added automatically if you don't include one.
<ui-link to="surface-slug">Label</ui-link>   Navigates to a sibling surface in the deck.
<ui-deck-nav></ui-deck-nav>                  Prev/next navigation chrome for the deck.

Translation note: you may also write ordinary HTML — `<h1>`/`<h2>`/`<h3>`, `<p>`, `<button>`,
`<form>`, `<select>`, and `<a data-to="slug">` are automatically rewritten into the matching
`<ui-*>` components in the browser (so they get styling + backflow wiring). Prefer the `<ui-*>`
components directly; the plain-HTML translation is a convenience.

Interaction flows back via wait_for_backflow / list_backflow:
  - a button yields { action, value }
  - a form yields  { action: "<form action>", value: { field: value, ... } }
